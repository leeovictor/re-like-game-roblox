# Objective Notification Animation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a one-second delayed objective notification with a 0.5-second fade in, five seconds fully visible, and a 0.5-second fade out.

**Architecture:** `useObjectiveNotification` will remain responsible for the notification lifecycle and will publish a batch only after the one-second entry delay. A shared timing module will keep the hook and UI synchronized. `App` will remain the owner of the React UI and will use `TweenService` plus a `TextLabel` ref to animate the label and its `UIStroke`, cancelling old tweens when a batch is replaced.

**Tech Stack:** Luau `--!strict`, Roblox `TweenService`, React 17.2.1, ReactRoblox 17.2.1, TestEZ in Roblox Studio, Rojo 7.7.0, Selene 0.29.0 and luau-lsp 1.69.0.

## Global Constraints

- The notification will wait one second before it is mounted, fade in for 0.5 seconds, remain fully visible for 5 seconds, fade out for 0.5 seconds, and then be removed.
- A new batch invalidates the previous lifecycle and restarts the one-second wait; batches are replaced rather than queued.
- `useObjectiveNotification` continues returning `{ ObjectiveView }?` and `ObjectiveController` remains unchanged.
- `App` remains the only owner of the visual React tree.
- Animate the objective notification text, background and `UIStroke`; do not animate the permanent inventory objective list.
- Do not change pickup notification timing or behavior.
- Specs of UI remain outside the TestEZ scope; verify the animation manually in Roblox Studio.
- Specs strict must create fixtures in `beforeEach` and destroy or disconnect everything in `afterEach`.
- After updating scripts or specs used by TestEZ, stop and restart the Play session before running tests.
- Do not edit `Packages/` or `DevPackages/`; those directories are generated by Wally.
- Preserve script-based imports and the existing client project mapping.
- Keep `--!strict`; do not use `--!nocheck`, broad ignores or disabled type errors.
- Do not revert or overwrite the unrelated local objective-system changes already present in the worktree; inspect same-file hunks before editing `useObjectiveNotification.luau` or `App.luau`.

### Task 1: Add Shared Timing and Delayed Notification Lifecycle

- Produces: a timing table with `entryDelay`, `fadeInDuration`, `visibleDuration` and `fadeOutDuration`; the unchanged `useObjectiveNotification(): { ObjectiveView }?` return contract.

- [ ] **Step 1: Create the shared timing module**

Create `src/client/objectives/ObjectiveNotificationTiming.luau` with no Roblox instance state and exactly these values:

```lua
--!strict

return {
	entryDelay = 1,
	fadeInDuration = 0.5,
	visibleDuration = 5,
	fadeOutDuration = 0.5,
}
```

The hook and `App` must require this module instead of declaring independent copies of the durations.

- [ ] **Step 2: Change the hook's initial state to hidden**

In `useObjectiveNotification.luau`, require the timing module and replace the current `useState(initialBatch)` initialization with a typed `nil` state:

```lua
local timing = require(script.Parent.ObjectiveNotificationTiming)

local batch, rawSetBatch = React.useState(nil :: { ObjectiveView }?)
```

Keep `initialBatch` from `controller.getState()` so the initial objective can still be scheduled after the component effect is installed.

- [ ] **Step 3: Add generation-guarded scheduling**

Inside the existing `React.useEffect`, connect the activation signal and use one local scheduler for both the initial batch and later batches. The scheduler must mount a batch after `timing.entryDelay`, then clear it after the fade in, visible interval and fade out:

```lua
	local function scheduleNotification(nextBatch: { ObjectiveView }, generation: number): ()
		task.delay(timing.entryDelay, function()
			if not active or generation ~= notificationGeneration then
				return
			end
			setBatch(nextBatch)
			task.delay(
				timing.fadeInDuration + timing.visibleDuration + timing.fadeOutDuration,
				function()
					if active and generation == notificationGeneration then
						setBatch(nil)
					end
				end
			)
		end)
	end
```

Connect `controller.activated` before scheduling `initialBatch`. For each activation, increment `notificationGeneration`, set the current batch to `nil` so the old React label unmounts, and call `scheduleNotification(nextBatch, currentGeneration)`. For the initial batch, increment the generation and schedule it only when it is non-nil and non-empty.

- [ ] **Step 4: Preserve cleanup and stale-callback protection**

Keep the existing `active` boolean and increment `notificationGeneration` in the effect cleanup before disconnecting the signal:

```lua
	return function()
		active = false
		notificationGeneration += 1
		connection:Disconnect()
	end
```

Do not use `task.cancel` or a queue. The generation comparison must be the mechanism that prevents an old delayed callback from mounting or clearing a newer batch.

### Task 2: Animate the Objective Notification in `App`

**Files:**
- Modify: `src/client/ui/App.luau:3-20,188-223`

**Interfaces:**
- Consumes: `useObjectiveNotification()`, `ObjectiveNotificationTiming`, and the `TextLabel`/`UIStroke` instances created by the existing `objectiveNotice` element.
- Produces: the same objective notice content and layout with the approved delayed fade lifecycle; no changed hook or controller API.

- [ ] **Step 1: Add the animation dependencies and ref**

Add the Roblox service and timing module near the existing imports:

```lua
local TweenService = game:GetService("TweenService")

local timing = require(script.Parent.Parent.objectives.ObjectiveNotificationTiming)
```

At the top of `App`, after the notification hook call, create a typed ref:

```lua
	local objectiveNotificationRef = React.useRef(nil :: TextLabel?)
```

Keep this ref local to `App`; it is only for the host instance created by React.

- [ ] **Step 2: Add the cancellable notification animation effect**

Add an effect that depends on `objectiveNotification`. It must return immediately when there is no batch or the ref has not been attached. Otherwise, find the existing child named `Stroke`, use it only when it is a `UIStroke`, create a label fade-in and stroke fade-in to the current visible values, and schedule the fade-out after the fade-in plus five seconds:

```lua
	React.useEffect(function()
		local notification = objectiveNotificationRef.current
		if objectiveNotification == nil or notification == nil then
			return
		end

		local active = true
		local strokeInstance = notification:FindFirstChild("Stroke")
		local stroke = if strokeInstance ~= nil and strokeInstance:IsA("UIStroke") then strokeInstance else nil
		local fadeOut: Tween? = nil
		local strokeFadeOut: Tween? = nil

		local fadeIn = TweenService:Create(notification, TweenInfo.new(timing.fadeInDuration), {
			TextTransparency = 0,
			BackgroundTransparency = 0.08,
		})
		local strokeFadeIn = if stroke ~= nil
			then TweenService:Create(stroke, TweenInfo.new(timing.fadeInDuration), { Transparency = 0.25 })
			else nil

		fadeIn:Play()
		if strokeFadeIn ~= nil then
			strokeFadeIn:Play()
		end

		task.delay(timing.fadeInDuration + timing.visibleDuration, function()
			if not active then
				return
			end
			fadeOut = TweenService:Create(notification, TweenInfo.new(timing.fadeOutDuration), {
				TextTransparency = 1,
				BackgroundTransparency = 1,
			})
			strokeFadeOut = if stroke ~= nil
				then TweenService:Create(stroke, TweenInfo.new(timing.fadeOutDuration), { Transparency = 1 })
				else nil
			fadeOut:Play()
			if strokeFadeOut ~= nil then
				strokeFadeOut:Play()
			end
		end)

		return function()
			active = false
			fadeIn:Cancel()
			if strokeFadeIn ~= nil then
				strokeFadeIn:Cancel()
			end
			if fadeOut ~= nil then
				fadeOut:Cancel()
			end
			if strokeFadeOut ~= nil then
				strokeFadeOut:Cancel()
			end
		end
	end, { objectiveNotification })
```

The `active` guard protects the delayed callback, while cleanup cancellation stops an in-progress tween when the hook replaces the batch or React unmounts the notice.

- [ ] **Step 3: Initialize the notice at full transparency and attach the ref**

In the existing `objectiveNotice` `TextLabel` props, add the ref and set the starting transparency values. Keep the existing visible `BackgroundTransparency`, and stroke color unchanged except for initializing its transparency:

```lua

```

Change the existing `Stroke` child property to:

```lua

```

The fade-in effect will restore `BackgroundTransparency = 0.08` and stroke transparency `0.25`, matching the current appearance.
